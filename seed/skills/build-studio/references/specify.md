Step: specify. Choose a feature id with the NNN-slug convention (`file_list('/Specs/user-specs')` to find the highest existing number; next = +1). Read `/Templates/commands/specify.md` and `/Templates/spec-template.md` with `file_read`, then write `/Specs/user-specs/<id>/spec.md` with `file_write` following the template: prioritized, independently-testable user stories; functional requirements; measurable success criteria. Mark unknowns with [NEEDS CLARIFICATION]. Set the **App Target** field to `bos-core`, `builtin-app`, `marketplace-item`, or `n/a` (see the target reference table in SKILL.md) — this is what `implement` and any later session consult to pick the right delegation mechanism, so don't leave it as the template placeholder. `marketplace-item` covers an app facet, a service facet, or both together — don't invent a separate "service" target; a spec that needs both a UI and a background daemon is still one `marketplace-item`. If it's genuinely unclear at specify time (e.g. built-in vs. marketplace hasn't been decided yet), mark it `[NEEDS CLARIFICATION]` like any other open question and resolve it no later than `clarify`.

**Before writing `bos-core` because the feature needs a protocol handler, arbitrary HTTP verbs, or a continuous background process, read `references/target-marketplace-item.md` first.** That reasoning ("Next.js can't handle X, therefore this needs BOS source") is exactly the mistake that reference exists to catch — such a need is usually a signal for a `marketplace-item`'s service facet (an installed item's own worker-thread process on its own port, entirely outside Next.js), not new `src/` routing. Don't let an Assumptions/Dependencies section bake in "must modify src/middleware.ts" (or similar) without checking this first — once written into spec.md, `plan` and `implement` will build on it as agreed fact.

**You write `spec.md`. Nothing else.** Not `service.json`, not `index.js`, not any config file, not a sketch of what the item will look like — even to make the spec feel more concrete. Implementation is a later, separate, delegated step (`implement`) — writing any implementation-shaped file during `specify` has happened for real and cost an entire session to (incompletely) undo. If you want to illustrate a shape, describe it in prose or a fenced code block INSIDE spec.md — never as its own file.
