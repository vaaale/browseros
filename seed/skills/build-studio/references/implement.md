## Handover to developer (dev_delegate)

Hand over the SPEC, not a restated version of it. The spec/plan/tasks store is mounted read-only at `specs/<store>/<id>/` inside the Developer's own worktree (020-branch-coupled-specs) — it can and should read spec.md/plan.md/tasks.md itself. Do not manually re-summarize the requirements, re-list every task, or re-transcribe the acceptance criteria into the task text: that's makework, and a paraphrase can silently drift from what the spec actually says. Two scenarios:

1. **Implement a spec** — delegating fresh implementation work: give the Developer the path (`specs/<store>/<id>/`) and instruct it to implement according to the plan and tasks; a one-line statement of what the feature is (so the task isn't cryptic on its own) is fine, a rewritten summary of the spec's contents is not.
2. **Followups** — delegating changes to an already in-progress implementation: give the Developer the path to the spec plus clear, concise instructions describing the NEW change you want made (this is genuinely new information, not in the spec yet — include it in full, verbatim if it's a user-reported problem). Also instruct the Developer to update the spec if the change warrants it.

In both cases, append these standing constraints: keep edits on the active feature branch; run `npx tsc --noEmit` and `npm run lint`, fix every error before finishing; update `docs/usage`/`docs/dev` if architecture changed; name any Playwright test file `e2e/<feature-id>.spec.ts`; follow the BOS style guide (`docs/dev/guides/style-guide.md`) and, for apps, the apps guide (`docs/dev/guides/apps.md`). `target-bos-core.md`/`target-builtin-app.md` point back here for the exact template — don't invent a competing one.

This does NOT apply to a marketplace-item delegation (`agent_delegate` with `contentOnly:true`): that run has no worktree and no spec mounted anywhere (`supervisorBegin`, which mounts `specs/`, only runs for non-`contentOnly` calls) — see `references/target-marketplace-item.md` for why its task text has to be a self-contained description instead of a path.
